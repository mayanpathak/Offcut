**Reader.** Whoever writes the code. The guide gives the order of work and the commands; `coding-promptsv6.1.md` gives the prompts an agent runs. A number nobody has measured is marked **(assumption)**. A fact that must be read on a real machine before the code relies on it is marked **(read in P171)**.

**The one-sentence goal.** At the end of V6.1, in a build with the flag `long_video` on, a signed-in person opens "Make shorts from a long video", drops a video of up to 45 minutes (4K or HEVC included), and watches its sound extracted and transcribed in the cloud, without the file ever being copied; a killed tab continues from the last saved window without the file, a cloud failure pauses with a reason and Continue, and the job ends with a master transcript the person can read; with the flags off, the product is exactly what it is at `2568a6e`.

**The second goal: nothing that works breaks (TS §41).** Every protected proof of TS §41.1 passes unchanged in the build production runs (flags off). With `long_video` and `high_res` on, the clip page behaves as at `2568a6e` except the rows DC-1 to DC-4 name. Production keeps both flags off at the merge (D-393); turning them on is a separate deploy, the founder's (§12.3).

**What you can demo.** In the flags-on build: open `/app/long`, drop a 45-minute 4K HEVC file, see "Reading the sound" then "Transcribing 7 of 32", kill the tab, reopen, press Continue: it finishes from the window it reached, without asking for the file; kill it again during the sound step: it asks for the same file, refuses a different one, accepts the right one. Switch the API's `TRANSCRIBE_ENABLED` off mid-job: the job pauses with "Transcription is off right now" and Continue. At the end, the transcript's sentences with their times. On `/app`, the reference clip behaves as today; `rej_4k.mp4` is accepted and exports at 1080 × 1920; a 2-minute file is refused with "Make shorts from it".

### 2.5 Audio

| # | Decision | Why |
|---|---|---|
| D-401 | **`offcut-dsp::resample::StreamResampler` (new, additive):** the same `rubato` `Fft` resampler as `resample_mono`, with the same `CHUNK_FRAMES`, fed in pieces; `push(&[f32]) -> Vec<f32>` and `finish(total_input_len) -> Vec<f32>`. Its whole output equals `resample_mono` over the concatenated input, sample for sample (a test with random piece sizes at 44.1 and 48 kHz). The WASM binding is a class, `StreamResampler` | `decodeAudio`'s one buffer of the whole track at the source rate is about 520 MB for 45 minutes at 48 kHz: the long path cannot hold it |
| D-402 | **`decodeAudioRegion(reader, info, from, to, onChunk, isCancelled)`** is built now (TS §43.5) and is the engine of `writeWholePcm16`, whose region is `[resume point, duration)`. | D-403 | **`pcm16.f32` is checkpointed by whole seconds:** after every 10 s written, the source row's `pcm16Seconds` is updated. A resume truncates the file to `pcm16Seconds × 16,000` samples and decodes from the audio sample at or before `pcm16Seconds − AAC_PREROLL`, dropping output before the resume point. Its final length is `round(duration × 16)` samples, padded with silence | At most 10 s of decoding is lost; the file never holds a half-written second |
| D-404 | **The source's reference level** for D-382's silence guard is computed while the audio is written: a histogram of absolute sample levels in 0.1 dB bins over the whole source, whose 95th percentile is stored in the source row as `levelP95` | A window of an intro or of silence would otherwise judge its words against its own quiet level (§8.4) |

```text

 4 video.codec == Hevc && !flags.high_res               → Hevc
 5 video.codec ∉ {H264, Hevc}                           → VideoCodec
 6 video.codec == Hevc && !decode                       → Hevc
 7 no audio track                                       → NoAudio
 8 first audio track's codec != Aac                     → AudioCodec
 9 long side > (high_res ? MAX_INPUT_LONG_SIDE : MAX_LONG_SIDE) → Resolution      // display size, after rotation
10 avg_fps > MAX_INPUT_FPS + INPUT_FPS_TOLERANCE        → FrameRate
11 video.is_hdr && !flags.hdr_ok                        → Hdr
12 !decode                                              → DecodeUnsupported
13 duration ≤ MAX_CLIP_DURATION && audio_tracks == 1    → Route::Clip
14 duration ≤ MAX_CLIP_DURATION                         → MultiAudioTrack
15 entry == Clip                                        → Duration
16 duration > MAX_SOURCE_DURATION                       → Duration
17 else                                                 → Route::Long(SourceInfo { audio_track: first, … })
```

`entry == Long` with `flags.long_video == false` is treated as `Entry::Clip` (a test). ## 7. Audio

### 7.1 `StreamResampler` (D-401)

```rust
// offcut-dsp/src/resample.rs, below resample_mono (unchanged)
pub struct StreamResampler { /* rubato Fft, pending input, output produced */ }
impl StreamResampler {
    pub fn new(from: Hz, to: Hz) -> Option<StreamResampler>;
    pub fn push(&mut self, input: &[f32]) -> Vec<f32>;
    pub fn finish(self, total_input: usize) -> Vec<f32>;   // flushes; total output = round(total_input × to / from)
}
```

Test (`stream_resample.rs`): for 48 kHz and 44.1 kHz noise of 7 minutes split at random sizes (seeded), the concatenated output equals `resample_mono` over the whole input, sample for sample; the delay trim and the length rule match.

### 7.2 `audio-region.ts`

```ts
export function decodeAudioRegion(reader: ByteReader, info: SourceInfo, from: SourceMs, to: SourceMs,
  onChunk: (mono: Float32Array, at: SourceMs, rate: Hz) => void, isCancelled: () => boolean): Promise<void | typeof CANCELLED>;
export function writeWholePcm16(sourceId: SourceId, reader: ByteReader, info: SourceInfo, fromSeconds: number,
  onProgress: (doneMs: number) => void, onSecond: (seconds: number) => void, isCancelled: () => boolean):
  Promise<{ levelP95: number } | typeof CANCELLED>;
```

- `decodeAudioRegion` follows `decodeTrack`'s structure (batches of 32 compressed samples, the 256-frame queue high-water, the same failure mapping), starting at the first audio sample whose time is at or before `from − AAC_PREROLL` (a binary search over the sample table), and emits at most 10 s of decoded mono per chunk. It keeps decoding when the decoded rate differs from the container's and reports the rate with each chunk.
- `writeWholePcm16` opens `sources/<id>/pcm16.f32` with a sync handle, truncates it to `fromSeconds × 16,000 × 4` bytes, feeds each chunk through a `StreamResampler` (rebuilt when the rate changes), writes the 16 kHz samples at their place, drops what lies before the resume point or after the duration, pads the tail with silence, calls `onSecond` after every 10 s of output (the source row's checkpoint, D-403), and updates the level histogram (D-404).
- **Memory:** one decoded chunk (10 s at 48 kHz, 1.9 MB) and the resampler's state. TE-17 reads the peak.

### 12.2 Deploy (dark)

3. **Founder or agent at the founder's request:** tag `v6.1` on the merge commit.

### 12.3 Turning a flag on in production (later, separate)

Vercel → Environment: `OFFCUT_FEATURES_ON=high_res` (or `long_video,high_res` after V6.4's alpha), then a re-run of the latest `main` run's `deploy-web` job, or the next pushed commit's: either one runs `vercel pull` (which brings the variable), `vercel build` and the test-key guard. **Never the Redeploy button** (memory). The founder does this (`overnight-run.md` §8). Off again: remove the name and deploy. A flag turned on changes no stored data (TS §41.3.7).

### 12.4 Rollback

A revert of the merge (`git revert -m 1`), one CI run. No server migration. **The browser database is the one trap:** a build that asks for structure version 1 cannot open a database already upgraded to 2 (the browser answers `VersionError`), and the reverted build is exactly such a build. So V6.1 ships, in `db.ts`, the rule of D-414: on `VersionError`, open the database at its own version and use only the stores this build knows. The rule protects every later rollback; the build reverted to (`2568a6e`) does not have it, so **while `long_video` is off in production no user's database is upgraded** (upgrade 2 runs only when the long page first opens the source stores, §9.1), and a rollback of V6.1 itself is safe.
